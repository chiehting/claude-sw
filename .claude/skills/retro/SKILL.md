在主對話執行。參數:`/retro NN`,NN 為功能編號。

## 目的
把 agents 的失誤和有效做法煉成 lesson:每條都能變成下一個功能會遵守的規則。

## 流程
1. **蒐集事實**,每條陳述都能指到來源(檔案、指令輸出、commit):
   - `docs/features/NN-*/spec.md`、`STATUS.md` 的狀態變化。
   - 測試迴圈與實作迴圈各跑了幾輪、每輪 verifier 的失敗項與 debugger 的根因與歸類。
   - `git log main..feat/NN-name`(於該 worktree)。
   - 既有 `docs/retro/*` 與 `docs/NOTES.md`(步驟 4 比對用)。
2. **寫入 `docs/retro/NN-name.md`**,精鍊:每項只留事實、證據與 lesson,依序:
   - **結果**:最終狀態、驗證輪數。
   - **順利的地方**:值得保留的做法。
   - **出問題的地方**:agent 或流程的失誤,只寫事實與證據。例:spec 的 AC 不可驗證、implementer 超出範圍、debugger 沒重現就下結論。
   - **學到的事**:每條是一條 lesson,格式見鐵則。
   - **下一步**:未完成事項,建議放進相關 spec 的「待決事項」或另開新 spec;由使用者以 `/write-spec` 處理。
3. **提出規則修改**:把「學到的事」整理成建議,**先給使用者看,同意後才寫入**。
   - 專案特有的注意事項(工具行為、環境限制、容易誤判的事)→ `docs/NOTES.md`。
   - 影響某個 agent 行為 → 該 agent 的 `.md`。
   - 難以反悔的決策 → ADR。新術語 → GLOSSARY。
4. **收斂**:每條「學到的事」比對步驟 1 的既有紀錄。同樣的結論出現第二次,就升格為規則,去處同步驟 3,同樣經使用者同意。
5. **淘汰**:逐條重審 `docs/NOTES.md` 既有條目,對照現行程式碼與 `docs/STACK.md`,列出已不成立、已被修掉或已被其他規則涵蓋的條目,提議刪除(經使用者同意才刪)。

## 完成條件

每條教訓都有去處(新規則、併入既有規則、或僅留歷史),且 NOTES 每個既有條目都已重審。

## 鐵則

- 只寫 `docs/retro/` 與使用者同意的規則修改;程式碼與 spec 維持原樣。
- lesson 與規則同格式:一行、可執行、可檢查、附來源(`retro/NN`)與失效條件(何時可刪,例如「某依賴升級後」);`docs/NOTES.md` 只收這樣的規則。
- retro 檔只是歷史紀錄,不是知識庫;agent 只讀規則檔,不讀 retro,所以教訓必須進規則檔才算生效。
